# 汇编语言 作业 7 · 递归调用：斐波那契数列

> 题目：**五、递归调用**
>
> 求斐波那契数列：`F(n) = F(n-1) + F(n-2)`，`F(0) = 0`，`F(1) = 1`。
>
> 环境：DOSBox 0.74-3 + MASM 5.10 / LINK 3.64 / DEBUG；C 部分使用 Turbo C++ 3.0（`TCC -ms`）。
>
> 仓库：<https://github.com/Rayrayray35/assembly-homework>

## 一、题目要求

1. 从键盘输入 `n`（`1 ≤ n ≤ 100`）；
2. 根据 `n` 值输出第 `n` 个斐波那契数；
3. 要求用**递归**实现；
4. 过程中要求使用**寄存器**；
5. 初始化栈空间，思考栈空间多大才不会发生 Stack Overflow；
6. 单步跟踪程序运行，观察每一次**调用或返回时栈空间的变化**；
7. 用 C 语言实现后查看反汇编代码并加注释。

## 二、动手之前先想清楚三件事

### 2.1 递归公式与调用次数

递归定义很直接：

```text
F(0) = 0
F(1) = 1
F(n) = F(n-1) + F(n-2)      n >= 2
```

但**朴素双递归的调用次数是指数级的**。设 `T(n)` 为计算 `F(n)` 需要的调用次数，则

```text
T(0) = T(1) = 1
T(n) = 1 + T(n-1) + T(n-2) = 2*F(n+1) - 1
```

| n | F(n) | 朴素递归调用次数 T(n) |
|---:|---:|---:|
| 10 | 55 | 177 |
| 20 | 6765 | 21 891 |
| 24 | 46 368 | 150 049 |
| 30 | 832 040 | 2 692 537 |
| 100 | 354 224 848 179 261 915 075 | ≈ 1.15 × 10²¹ |

`n = 100` 时约 `10²¹` 次调用，即使一秒能跑一亿次也要跑几十万年。**题目要求 1..100，所以必须消除重复计算**。

做法：**记忆化（memo）**。把算过的 `F(k)` 存进 `memo[k]`，下次再要就直接返回。这样每个 `k` 只算一次，总调用次数约 `2n+1 ≈ 201` 次，同时**递归的形态和深度完全没有变**（`F(100)` 仍然一层层调到 `F(0)` 再返回），正好满足"递归实现"并用来观察栈。

### 2.2 数值范围：必须用十进制大数

| 类型 | 最大值 | 能算到 |
|---|---:|---|
| 16 位无符号 | 65 535 | F(24) = 46 368，F(25) = 75 025 已溢出 |
| 32 位无符号 | 4 294 967 295 | F(47) = 2 971 215 073，F(48) 已溢出 |
| F(100) | 354 224 848 179 261 915 075 | **21 位十进制** |

所以汇编版用 **24 字节存 24 位十进制数字**（低位字节在前，小端），加法逐位相加、满 10 进 1；C 版用 `unsigned char memo[101][24]` 做同样的事。

### 2.3 栈空间要多大

栈是"每调用一层就压一帧，返回一层就弹一帧"。只要算出**单层帧大小 × 最大深度**即可：

| 程序 | 单层帧 | 最大深度 | 需要栈 | 实际开辟 |
|---|---:|---:|---:|---:|
| `FIB.ASM`（大数+记忆化） | 16 B | 101 层（n..0） | 1 616 B | **4 KB**（2 048 字） |
| `FIB16.ASM`（16 位朴素版） | 8 B | 25 层（n..0） | 200 B | 1 KB |
| `FIB_DBG.ASM`（DEBUG 用，n=5） | 8 B | 6 层 | 48 B | 512 B |
| C `fib()`（32 位返回值） | 8 B + 4 B 暂存 | 21 层（n=20） | < 300 B | TC 默认栈 |
| C `fibbig()`（大数+记忆化） | 12 B | 101 层 | 1 212 B | TC 默认栈 |

`FIB.ASM` 的 16 字节是这样来的：

```text
[bp+2]  返回地址        CALL 压入                  2 B
[bp+0]  调用者的 bp     PUSH BP                    2 B
[bp-2]  局部变量 n      SUB SP,2                   2 B
[bp-4]  保存的 bx       PUSH BX                    2 B
[bp-6]  保存的 cx       PUSH CX                    2 B
[bp-8]  保存的 dx       PUSH DX                    2 B
[bp-10] 保存的 si       PUSH SI                    2 B
[bp-12] 保存的 di       PUSH DI                    2 B
                        ------------------------------
                        合计                       16 B
```

101 × 16 = 1 616 B，声明 4 KB 留了 2.5 倍余量；DOS 的 `INT 21H` 中断处理也在栈上工作，留余量是必要的。

## 四、汇编实现（`src/07_fib/fib.asm`）

### 4.1 数据布局

```asm
DIGITS  equ 24                      ; 每个数 24 位十进制
MAXN    equ 100

memo    db (MAXN+1)*DIGITS dup(0)   ; memo[n]：24 字节，memo[n][0] 是最低位
valid   db (MAXN+1) dup(0)          ; valid[n]：1 表示算过
```

`memo` 相当于 `unsigned char memo[101][24]`，`memo[n]` 的地址 = `memo + n*24`。取地址用 `MUL`：

```asm
mov  ax,n
mov  cx,DIGITS
mul  cx                 ; DX:AX = n*24
mov  di,offset memo
add  di,ax              ; DI = &memo[n]
```

### 4.2 递归过程 `fib_rec`

**寄存器约定（要求 4）**：

| 寄存器 | 用途 |
|---|---|
| `AX` | 入口参数 `n`；加法时作累加/临时 |
| `DI` | 结果缓冲区指针 `&memo[n]` |
| `BX` | 过程内部保存 `n` |
| `CX` | 循环计数（24 位） |
| `SI` | 指向 `memo[n-1]` |
| `DX` | 指向 `memo[n]`（加法目标） |
| `AH` | 进位 |

入口先保护现场，出口逆序恢复：

```asm
fib_rec proc
        push bp
        mov  bp,sp
        sub  sp,2               ; [bp-2] = n
        push bx
        push cx
        push dx
        push si
        push di

        mov  [bp-2],ax
        mov  bx,ax
        cmp  byte ptr valid[bx],0
        je   fr_notdone
        jmp  fr_done            ; 记忆化：算过就直接返回

fr_notdone:
        cmp  bx,0
        jne  fr_try1
        jmp  fr_mark            ; F(0) = 0，memo[0] 本来就是 0
fr_try1:
        cmp  bx,1
        jne  fr_rec
        mov  byte ptr [di],1    ; F(1) = 1
        jmp  fr_mark
```

递归主体——**先算 `F(n-1)`，再算 `F(n-2)`，最后相加**：

```asm
fr_rec:
        mov  ax,bx
        dec  ax
        mov  cx,DIGITS
        mul  cx
        mov  di,offset memo
        add  di,ax              ; DI = &memo[n-1]
        mov  ax,bx
        dec  ax
        call fib_rec            ; ★ 递归第一层

        mov  ax,bx
        sub  ax,2
        mov  cx,DIGITS
        mul  cx
        mov  di,offset memo
        add  di,ax              ; DI = &memo[n-2]
        mov  ax,bx
        sub  ax,2
        call fib_rec            ; ★ 递归第二层
```

### 4.3 逐位相加

```asm
        mov  cx,DIGITS          ; 24 位
        xor  ah,ah              ; AH = 进位
fr_add:
        mov  al,[si]            ; a[i]
        add  al,[di]            ; + b[i]
        add  al,ah              ; + 进位
        xor  ah,ah
        cmp  al,10
        jb   fr_store
        sub  al,10              ; 满 10 进 1
        mov  ah,1
fr_store:
        mov  [bx],al            ; memo[n][i]
        inc  si
        inc  di
        inc  bx
        loop fr_add
```

> 这里踩过一个坑：最初把结果指针放在 `DX` 里写 `mov [dx],al`，MASM 报 **A2048: Must be index or base register**——8086 只有 `BX/BP/SI/DI` 能做基址/变址，`DX` 不行，改用 `BX` 后通过。

### 4.4 输入与输出

- 输入用 `INT 21H` 的 `0AH` 缓冲输入，缓冲区格式为 `最大长度, 实际长度, 字符...`；
- **`0AH` 会把结尾的回车 `0Dh` 也存进缓冲区并计入长度**，所以转换时必须先判断 `AL = 13` 结束，否则会把回车当非法字符（这个坑让第一版对任何输入都返回 0）；
- 输出大数时从最高位往下找第一个非零位，再逐位 `+ '0'` 输出，避免前导零；
- 主程序先校验 `1 ≤ n ≤ 100`，越界输出错误提示。

## 五、栈空间与"调用/返回时栈的变化"（要求 5、6）

### 5.1 程序自带的轨迹输出

`FIB16.ASM` 在 `n ≤ 8` 时会把每次**进入**和**返回**时的 `bp`（= 本层帧基址）和栈深度打印出来。`n = 5` 的完整轨迹（`evidence/07_fib/OUT_FIB16_TRACE_5.TXT`）：

```text
n (1-24): 5
[in ] n=5 sp=03FC depth=4
[in ] n=4 sp=03F4 depth=12
[in ] n=3 sp=03EC depth=20
[in ] n=2 sp=03E4 depth=28
[in ] n=1 sp=03DC depth=36
[out] n=1 sp=03E0 depth=32 F=1
[in ] n=0 sp=03DC depth=36
[out] n=0 sp=03E0 depth=32 F=0
[out] n=2 sp=03E8 depth=24 F=1
[in ] n=1 sp=03E4 depth=28
[out] n=1 sp=03E0 depth=32 F=1
[out] n=3 sp=03EC depth=20 F=2
[in ] n=2 sp=03EC depth=20
[in ] n=1 sp=03E4 depth=28
[out] n=1 sp=03E0 depth=32 F=1
[in ] n=0 sp=03E4 depth=28
[out] n=0 sp=03E0 depth=32 F=0
[out] n=2 sp=03E8 depth=24 F=1
[out] n=4 sp=03F0 depth=16 F=3
[in ] n=3 sp=03F4 depth=12
[in ] n=2 sp=03EC depth=20
[in ] n=1 sp=03E4 depth=28
[out] n=1 sp=03E0 depth=32 F=1
[in ] n=0 sp=03E4 depth=28
[out] n=0 sp=03E0 depth=32 F=0
[out] n=2 sp=03E8 depth=24 F=1
[in ] n=1 sp=03EC depth=20
[out] n=1 sp=03E8 depth=24 F=1
[out] n=3 sp=03F0 depth=16 F=2
[out] n=5 sp=0400 depth=0 F=5
F(n) = 5
```

读法（栈从高地址向低地址生长，`sptop = 0400H`）：

| 时刻 | 帧基址 BP | 深度 | 说明 |
|---|---:|---:|---|
| 进入 `F(5)` | `03FC` | 4 | 主程序 `CALL` 之后 |
| 进入 `F(4)` | `03F4` | 12 | **SP 减 8**：返回地址 2 + 旧 BP 2 + 局部 2 + BX 2 |
| 进入 `F(3)` | `03EC` | 20 | 又减 8 |
| 进入 `F(2)` | `03E4` | 28 | |
| 进入 `F(1)` | `03DC` | 36 | 最深一层（5 层） |
| 返回 `F(1)` | `03E0` | 32 | **SP 加 8**（`out` 打印的是 `ret` 之后的 SP） |
| 返回 `F(2)` | `03E8` | 24 | 又加 8 |
| … | … | … | 逐层弹栈 |
| 返回 `F(5)` | `0400` | **0** | 栈完全恢复到调用前 |

要点：

- **调用时**：`CALL` 压返回地址，被调过程再 `PUSH BP`、`SUB SP,2`、`PUSH BX`，SP 一共减 8；
- **返回时**：`POP BX`、`MOV SP,BP`、`POP BP`、`RET`，SP 一共加 8；
- 最深处的深度是 `4 + 8×(n-1) = 36`，`n=5` 时最深 5 层，与 2.3 节的公式一致；
- 整个过程中的峰值栈用量 = `4 + 8×n` 字节，本例 n=5 只有 44 字节。

### 5.2 DEBUG 单步复核

`src/07_fib/fib_dbg.asm` 是专门给 DEBUG 用的最小程序（n 固定为 5，没有任何输入输出，避免 `INT 21H` 干扰）。从 `FIB_DBG.LST` / `FIB_DBG.MAP` 查到递归过程入口 `0013H`、`ret` 在 `003EH`（代码段从 0 开始）：

```text
C:\FIB7>DEBUG FIB_DBG.EXE
-u 0013 003F          ; 看递归过程的反汇编
-g 0013               ; 停在 F(5) 入口, 记下 SP、BP
-t -t -t -t           ; 单步 push bp / mov bp,sp / sub sp,2 / push bx
                      ; 可以亲眼看到 SP 每步减 2, BP 落在帧基址
-g 0013               ; 继续运行, 停在 F(4) 入口: SP 又减 8
-g 0013               ; F(3) …… 一直下到 F(0)
-g 003E               ; 停在 ret 之前, SP 逐层加 8, 直到回到主程序
-q
```

本机 DOSBox 的 DEBUG 输出是直接写显存的，`>` 重定向到文件只会得到空文件，所以仓库里保存的是程序自动打印的同一组 `BP/SP/深度` 数据（上表）。两者观察的是同一件事：**每进一层 SP 减 8（本程序帧大小），每出一层 SP 加 8，最终回到 0400H**。

## 六、C 语言实现与反汇编（要求 7）

### 6.1 `fib.c`：32 位朴素递归

```c
unsigned long fib(unsigned n)
{
    if (n < 2)
        return n;
    return fib(n - 1) + fib(n - 2);
}
```

`TCC -ms -S FIB.C` 生成的关键代码（完整注释见 `src/07_fib/fib_c_annotated.asm`）：

```asm
_fib    proc    near
        push    bp
        mov     bp,sp
        push    si
        mov     si,word ptr [bp+4]      ; SI = n（参数在 bp+4）
        cmp     si,2
        jae     short @1@86
        mov     ax,si
        xor     dx,dx                   ; 32 位返回值：DX:AX
        jmp     short @1@114
@1@86:
        mov     ax,si
        dec     ax
        push    ax
        call    near ptr _fib           ; 递归 F(n-1)
        pop     cx
        push    ax                      ; ★ 保存 F(n-1) 低 16 位
        push    dx                      ; ★ 保存高 16 位（共 4 字节）
        mov     ax,si
        sub     ax,2
        push    ax
        call    near ptr _fib           ; 递归 F(n-2)
        pop     cx
        mov     bx,dx
        pop     dx
        pop     cx
        add     cx,ax                   ; 低 16 位加
        adc     dx,bx                   ; 高 16 位带进位加
        mov     ax,cx
@1@114:
        pop     si
        pop     bp
        ret
```

观察到的几个点：

1. **参数在 `[bp+4]`**：`CALL` 压 2 字节返回地址，再往上是实参；
2. 每层固定 `push bp / push si`，**帧 8 字节**（含返回地址和参数）；
3. 32 位返回值放 `DX:AX`，加法必须 `add` + `adc`；
4. 第二次递归期间，`F(n-1)` 的 4 个字节被压在栈上——这是 32 位运算带来的额外栈开销，汇编版用 16 位大数只占 2 字节。

### 6.2 `fibbig.c`：大数 + 记忆化（与汇编同算法）

```c
static void fib(int n)
{
    int i;
    unsigned t;
    unsigned carry = 0;

    if (done[n])
        return;
    if (n < 2) {
        memo[n][0] = (unsigned char)n;
        done[n] = 1;
        return;
    }

    fib(n - 1);
    fib(n - 2);

    for (i = 0; i < DIG; i++) {
        t = (unsigned)memo[n - 1][i] + memo[n - 2][i] + carry;
        memo[n][i] = (unsigned char)(t % 10);
        carry = t / 10;
    }
    done[n] = 1;
}
```

反汇编里最典型的两处（完整注释见 `src/07_fib/fibbig_c_annotated.asm`）：

```asm
; done[n] 检查 —— 记忆化
        mov     bx,word ptr [bp+4]
        cmp     byte ptr DGROUP:done[bx],0
        je      short @1@86
        jmp     @1@282                  ; 直接返回

; &memo[n][i] = memo + n*24 + i
        mov     ax,word ptr [bp+4]
        mov     dx,24
        imul    dx                      ; 32 位乘法
        mov     bx,ax
        mov     al,byte ptr DGROUP:memo[bx+si-24]   ; memo[n-1][i]
        ...
        mov     al,byte ptr DGROUP:memo[bx+si-48]   ; memo[n-2][i]

; memo[n][i] = t % 10;  carry = t / 10;  编译器做了两次 DIV
        mov     ax,di
        mov     bx,10
        xor     dx,dx
        div     bx
        ...
        mov     ax,di
        mov     bx,10
        xor     dx,dx
        div     bx
        mov     word ptr [bp-2],ax
```

### 6.3 汇编版 vs C 版

| 项目 | `FIB.ASM` | C `fibbig` |
|---|---|---|
| 数值表示 | 24 字节十进制大数 | `unsigned char memo[101][24]` |
| 参数传递 | `AX = n`，`DI = 结果指针` | 栈上传参，`[bp+4]` |
| 返回值 | 写入 `[DI]` | `void`，写全局 `memo[n]` |
| 每层帧 | 16 B | 12 B |
| 循环计数 | `CX` + `LOOP` | `SI` + `CMP/JL` |
| 乘法 | `MUL`（无符号） | `IMUL`（有符号） |
| 取模/除法 | 手工逐位减 10 | `DIV` 两次 |
| 记忆化标志 | `valid[n]` | `done[n]` |

### 7.2 踩过的坑

1. **`A2053: Jump out of range by 9 byte(s)`**
   `fib_rec` 里 `jne fr_done` 跨了 60 多行，条件跳转只有 ±127 字节。改成
   `je fr_notdone` + `jmp fr_done`（`JMP` 是 NEAR，够远）。

2. **`A2048: Must be index or base register`**
   `mov [dx],al` —— 8086 的基址寄存器只能是 `BX/BP/SI/DI`。把结果指针改放 `BX`。

3. **`0AH` 输入把回车也存进缓冲区**
   输入 `100` 时 `inbuf[1] = 4`，最后一个是 `0Dh`，被当成非法字符。加一条
   `cmp al,13 / je 结束` 后正常。

4. **朴素递归不能直接跑 n=100**
   第一版没加记忆化，n=20 还能秒出，n=30 就要等几秒，n=100 根本跑不完。
   加了 `valid[]` 后 n=100 瞬间出结果，而递归深度仍然是 101 层——知识点和性能都保住了。

5. **8.3 文件名限制**
   DOSBox 挂载目录虽然支持长文件名，但 DOS 程序只认 8.3。`FIB_TRACE.ASM`（9 个字符）
   在 DOS 里变成 `FIB_TRAC.ASM`，MASM 报 `Unable to open input file`。改成
   `FIBTRACE.ASM` 后正常。

6. **`[SP]` 不能直接寻址**
   `or word ptr [sp],0100h` 编译不过，8086 的 `SP` 不能作为基址寄存器；
   要先 `mov bp,sp` 再用 `[bp]`（本项目最终没用这种方式，但值得记一笔）。

7. **栈大小不要"拍脑袋"**
   先算 `帧大小 × 最大深度`，再乘 2~3 倍余量；DOS 的中断处理也要用同一段栈。

## 八、小结

1. **递归的本质是栈**：每层调用压入返回地址、旧 `BP`、局部变量和需要保护的寄存器；返回时逆序弹出。`n=5` 时 SP 从 `0400H` 一路减到 `03DCH`，再原路回到 `0400H`，轨迹和"每层 8 字节"完全对得上。
2. **递归不等于低效，重复计算才低效**：`T(n)=2F(n+1)-1` 的指数爆炸可以用记忆化压到 `O(n)`，递归结构不变。
3. **数值范围决定了数据结构**：`F(100)` 有 21 位，16 位、32 位寄存器都不够，必须自己实现十进制大数。
4. **寄存器是汇编的"变量"**：`AX` 传参、`DI` 传地址、`BX` 存 `n`、`CX` 计数、`AH` 做进位，先想清楚谁存什么，代码才不会互相踩。
5. **看反汇编能验证课本结论**：C 的递归帧、参数位置 `[bp+4]`、`DX:AX` 返回值、`add/adc` 双字加法，在 `TCC -S` 的输出里一目了然。
