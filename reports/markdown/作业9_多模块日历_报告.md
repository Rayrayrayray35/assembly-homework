## 二、模块划分

### 2.1 四个源程序 + 一个宏文件

| 文件 | 逻辑功能 | 主要符号 |
|---|---|---|
| `CALMAIN.ASM` | 主程序、键盘输入、年份/月份校验 | `start`、`read_dec` |
| `CALDATE.ASM` | 日期计算：闰年、月天数、Zeller 星期 | `is_leap_reg`、`month_days_reg`、`first_weekday_reg` |
| `CALDISP.ASM` | 月历显示：标题、表头、日期网格 | `show_calendar`、`print_grid`、`putdec2` |
| `CALDATA.ASM` | 公共数据段：变量、提示、月份表 | `cur_year`、`mdays`、`mnames` 等 |
| `CALMAC.INC` | 宏定义 | `PRINTSTR`、`NEWLINE`、`SAVEREGS`、`PROLOG` 等 |

调用关系：

```text
CALMAIN  ──近调用──>  show_calendar (CALDISP)
   │                         │
   │                         ├──近调用──> month_days_reg / first_weekday_reg (CALDATE)
   │                         └──读/写──> cur_year / cur_month / mdays / mnames (CALDATA)
   │
   └──读/写──> inbuf / p_year / p_month / e_year / e_month (CALDATA)
```

三个代码模块都使用同名的 `CSEG` 段。LINK 把 `CALMAIN`、`CALDATE`、`CALDISP` 的 `CSEG` 合并成一个物理代码段，所以模块之间的过程调用是 **NEAR CALL**（`E8 rel16`），不需要换 CS。

### 2.2 PUBLIC / EXTRN

`CALDATA.ASM` 里把其他模块要用的符号声明为 `PUBLIC`：

```asm
PUBLIC cur_year, cur_month, cur_days, cur_wd
PUBLIC inbuf
PUBLIC p_year, p_month, e_year, e_month
PUBLIC weekhdr
PUBLIC mdays, mnames
```

其他模块用 `EXTRN` 引用：

```asm
; CALMAIN
EXTRN show_calendar:near
EXTRN cur_year:word, cur_month:word
EXTRN inbuf:byte
EXTRN p_year:byte, p_month:byte, e_year:byte, e_month:byte

; CALDATE
EXTRN mdays:word

; CALDISP
EXTRN cur_year:word, cur_month:word, cur_days:word, cur_wd:word
EXTRN weekhdr:byte, mnames:word
EXTRN month_days_reg:near, first_weekday_reg:near
```

**关键细节：`EXTRN` 要写在 `CSEG segment` 之前。** 如果写在段内，MASM 5.10 会把外部符号记成“当前段（CSEG）的 External”，LINK 时报：

```text
error L2002: fixup overflow at 0006 in segment CSEG
target external 'P_YEAR'
```

把 `EXTRN` 移到所有 `SEGMENT` 之外后，LST 的符号表变成 `External`（没有段属性），LINK 才能按定义模块的段去解析。

### 2.3 数据组 DGROUP

`CALDATA.ASM` 定义：

```asm
DGROUP  group   DATA
DATA    segment para public 'DATA'
...
DATA    ends
```

`CALMAIN`、`CALDATE`、`CALDISP` 也声明一个空的 `DATA` 段并加入同一个 `DGROUP`：

```asm
DGROUP  group   DATA
DATA    segment para public 'DATA'
DATA    ends
```

主程序用 `MOV AX,DGROUP` / `MOV DS,AX` 设置 DS。这样所有模块的 `cur_year`、`mdays` 等符号都是 **DGROUP 内的近偏移**，可以直接用 `MOV AX,cur_year`、`MOV BX,OFFSET mdays`。

### 2.4 LINK 后的段布局

`CAL.MAP`：

```text
 Start  Stop   Length Name                   Class
 00000H 001FFH 00200H STACK                  STACK
 00200H 0030CH 0010DH DATA                   DATA
 00310H 005E8H 002D9H CSEG                   CODE

 Origin   Group
 0020:0   DGROUP

Program entry point at 0031:0000
```

`CSEG` 长度 `02D9H`，是三个代码模块（CALMAIN/CALDATE/CALDISP）合并后的结果。`show_calendar` 在合并后的 `CSEG:01A0H`，不是它自己文件里的偏移 0。

## 三、宏汇编

`CALMAC.INC` 定义了 5 个宏：

```asm
PRINTSTR macro msg
        mov  dx,offset msg
        mov  ah,9
        int  21h
endm

NEWLINE macro
        push ax
        push dx
        mov  dl,13
        mov  ah,2
        int  21h
        mov  dl,10
        mov  ah,2
        int  21h
        pop  dx
        pop  ax
endm

SAVEREGS macro
        push ax
        push bx
        push cx
        push dx
        push si
        push di
endm

RESTOREREGS macro
        pop  di
        pop  si
        pop  dx
        pop  cx
        pop  bx
        pop  ax
endm

PROLOG macro
        push bp
        mov  bp,sp
endm

EPILOG macro
        pop  bp
        ret
endm
```

### 3.1 宏的展开

`CALMAIN.ASM` 里：

```asm
year_again:
        PRINTSTR p_year
```

`CALMAIN.LST` 展开成：

```text
0005  BA 0010 R          mov dx,offset p_year
0008  B4 09             mov ah,9
000A  CD 21             int 21h
```

`show_calendar` 里：

```asm
show_calendar proc near
        PROLOG
        SAVEREGS
```

展开成：

```text
0000  55               push bp
0001  8B EC            mov bp,sp
0003  50               push ax
0004  53               push bx
0005  51               push cx
0006  52               push dx
0007  56               push si
0008  57               push di
```

`EPILOG` 展开成 `pop bp` / `ret`。

### 3.2 宏 vs 过程

| 项目 | 宏（Macro） | 过程（Procedure） |
|---|---|---|
| 展开时机 | 汇编时 | 运行时 |
| 机器码 | 每用一次复制一份 | 只有一份，靠 CALL/RET |
| 速度 | 快，没有 CALL/RET 和栈操作 | 慢一些，有调用开销 |
| 代码体积 | 变大 | 小 |
| 参数 | 编译期文本替换，可传符号/常量 | 寄存器/内存/栈 |
| 可读性 | 短小片段方便 | 复杂逻辑更清晰 |
| 本程序用途 | 打印字符串、换行、保护寄存器、过程框架 | 日期计算、显示网格 |

结论：**短小、频繁、参数简单的片段用宏；逻辑复杂、需要复用代码空间的过程用 CALL/RET。** 本程序两者都用了。

## 四、三种 CALL 的机器码对比

### 4.1 一个代码段内：近调用 E8 rel16

`CALMAIN.ASM` 的 `read_dec` 与主程序在同一个 `CSEG`：

```text
000C  E8 0062 R        call read_dec
```

`read_dec` 在 `CSEG:0062H`，`call` 的下一条指令在 `000FH`：

```text
位移 = 0062H - 000FH = 0053H
```

`CAL.EXE` 中 `CSEG:000C` 的实际字节：

```text
E8 53 00
```

执行时：

```text
SP = SP - 2
[SP] = 000FH        ; 返回 IP
CS 不变
```

返回时 `RET`（`C3`）弹出 2 字节 IP。

### 4.2 同一文件、不同代码段：远调用 9A off seg

`CALLDEMO.ASM` 里有两个代码段：

```asm
CSEG    segment para public 'CODE'
...
        call nearproc               ; 同一 CSEG, 近调用
...
CSEG    ends

FCODE   segment para public 'CODE'
farproc proc far
...
        ret                         ; CB
farproc endp
FCODE   ends
```

`CALLDEMO.LST`：

```text
000C  E8 002E R        call nearproc
001D  9A 0000 ---- R   call far ptr farproc
0007  CB              ret
```

最终 `CALLDEMO.EXE`：

```text
文件偏移 031CH: E8 1F 00          ; nearproc 在 CSEG:002E
文件偏移 032DH: 9A 00 00 15 00    ; farproc 在 FCODE:0000, 段值 0015H
```

执行时：

```text
近调用: SP-2, [SP]=返回 IP, CS 不变
远调用: SP-4, [SP]=返回 IP, [SP+2]=返回 CS, CS 换成 FCODE
```

返回时：

```text
nearproc: RET  (C3)  只弹 IP
farproc : RETF (CB)  弹 IP 和 CS
```

### 4.3 多个文件、同段合并：近调用 + 链接期重定位

`CALMAIN` 调用 `CALDISP` 的 `show_calendar`，两个文件都用 `CSEG`：

```text
CALMAIN.LST:
0057  E8 0000 E        call show_calendar
```

这里的 `0000 E` 是**占位位移 + 外部重定位**，汇编时还不知道 `show_calendar` 的最终位置。LINK 合并 `CSEG` 后填入真正的位移：

```text
CAL.EXE 文件偏移 0567H: E8 46 01
```

`show_calendar` 在合并后的 `CSEG:01A0H`：

```text
下一条 IP = 005AH
位移 = 01A0H - 005AH = 0146H
```

同样，`CNMAIN + CNLIB` 两个文件的近调用：

```text
CNMAIN.LST: 000C  E8 0000 E   call nearlib
CN.EXE:     E8 11 00          ; nearlib 在 CSEG:0020H
```

特点：

- 源文件里是 `E8 0000 E`；
- 链接时才填 16 位位移；
- CS 不变，仍在同一个物理代码段；
- 如果两个文件的段名不同，LINK 不会合并，近调用就无法解析。

### 4.4 多个文件、不同段：远调用 9A + 两个重定位

`CFMAIN` 调用 `CFLIB` 的 `farlib`，`CFLIB` 使用独立的 `FCODE` 段：

```text
CFMAIN.LST:
000C  9A 0000 ---- E   call far ptr farlib
```

最终 `CF.EXE`：

```text
文件偏移 02ECH: 9A 00 00 0D 00
```

`farlib` 在 `FCODE:0000H`，`FCODE` 在 MAP 中从 `00D0H` 字节开始 = `000DH` 段。

**这里踩过一个多文件特有的坑：**

如果 `CFMAIN.ASM` 不声明 `FCODE` 段名，MASM/LINK 3.64 会把 `farlib` 的远指针解析成：

```text
9A 20 00 05 00
```

即 `CS = CSEG 段 (0005H)`，`IP = 0020H`。由于 `CSEG` 在 `0050H` 字节、`FCODE` 在 `0070H` 字节，`0050H + 0020H = 0070H`，物理地址刚好落在 `FCODE` 上，程序“碰巧能跑”，但 **CS 仍然是 CSEG，不是真正的段间切换**。

在 `CFMAIN.ASM` 里加一个空的 `FCODE` 段声明后：

```asm
FCODE   segment para public 'CODE'
FCODE   ends

extrn  farlib:far
```

才得到正确的：

```text
9A 00 00 0D 00
```

这说明：**多文件远调用时，调用方也要知道目标段名；否则链接器可能用“当前段 + 连续偏移”来凑地址。**

### 4.5 汇总表

| 场景 | 源文件写法 | LST 机器码 | 最终 EXE | CS 是否改变 | 栈变化 |
|---|---|---|---:|---:|---:|
| 同一代码段 | `call read_dec` | `E8 0062 R` | `E8 53 00` | 否 | SP-2 |
| 同一文件、不同段（近） | `call nearproc` | `E8 002E R` | `E8 1F 00` | 否 | SP-2 |
| 同一文件、不同段（远） | `call far ptr farproc` | `9A 0000 ---- R` | `9A 00 00 15 00` | **是** | SP-4 |
| 多文件、同段合并 | `call show_calendar` | `E8 0000 E` | `E8 46 01` | 否 | SP-2 |
| 多文件、不同段 | `call far ptr farlib` | `9A 0000 ---- E` | `9A 00 00 0D 00` | **是** | SP-4 |

## 五、单步观察 CALL / RET 前后的 CS、IP、SP 和栈

`CALLTRACE.ASM` 在每次近/远调用前后打印 CS、IP、SP，并在被调过程入口打印 `[SP]`、`[SP+2]`。实际输出（`OUT_CALLTRACE.TXT`）：

```text
near before:  CS=01CC IP=0005 SP=0200
near entry :  CS=01CC IP=003E SP=01FE
 [SP]=0013 [SP+2]=A3B8
near after :  CS=01CC IP=0013 SP=0200

far  before:  CS=01CC IP=001E SP=0200
far  entry :  CS=01DC IP=0000 SP=01FC
 [SP]=002E [SP+2]=01CC
far  after :  CS=01CC IP=002E SP=0200
```

### 5.1 近调用 `call nearproc`

| 时刻 | CS | IP | SP | 栈顶 |
|---|---:|---:|---:|---:|
| 调用前 | `01CC` | `0005` | `0200` | — |
| 入口 | `01CC` | `003E` | `01FE` | `[SP]=0013` |
| 返回后 | `01CC` | `0013` | `0200` | — |

- `SP` 从 `0200` 减到 `01FE`，正好 **2 字节**；
- `[SP]=0013` 就是 `call nearproc` 的下一条指令 IP；
- CS 始终是 `01CC`，没有变化；
- `RET`（`C3`）弹出 2 字节 IP，SP 恢复到 `0200`。

### 5.2 远调用 `call far ptr farproc`

| 时刻 | CS | IP | SP | 栈顶 |
|---|---:|---:|---:|---:|
| 调用前 | `01CC` | `001E` | `0200` | — |
| 入口 | `01DC` | `0000` | `01FC` | `[SP]=002E`，`[SP+2]=01CC` |
| 返回后 | `01CC` | `002E` | `0200` | — |

- `SP` 从 `0200` 减到 `01FC`，正好 **4 字节**；
- `[SP]=002E` 是返回 IP；
- `[SP+2]=01CC` 是返回 CS；
- CS 从 `01CC` 变成 `01DC`，这是 `FCODE` 段；
- `RETF`（`CB`）依次弹出 IP、CS，SP 恢复到 `0200`，CS 回到 `01CC`。

### 5.3 用 DEBUG 复核

`CTRACE.LST` 给出：

```text
CSEG:0010  E8 003E R   call nearproc
CSEG:0029  9A 0000 R   call far ptr farproc
CSEG:003E  ...         nearproc
FCODE:0000 ...         farproc
```

在 DEBUG 中可以：

```text
-g 0010        ; 停在近调用前, 记 CS、IP、SP
-t             ; 单步 CALL, 看 SP 减 2、[SP] 变成返回 IP
-g 003E        ; 停在 nearproc 入口
-g 0029        ; 停在远调用前
-t             ; 单步 CALL FAR, 看 SP 减 4、CS 变 FCODE、[SP]/[SP+2]
```

本机 DOSBox 的 DEBUG 输出直接写显存，`>` 重定向只能得到空文件，所以仓库里保存的是程序自动打印的同一组 `CS/IP/SP/[SP]/[SP+2]` 数据，效果与单步观察一致。

## 七、构建与踩坑

### 7.1 构建

每个模块单独汇编，再一起链接：

```dos

MASM CALDATE.ASM,CALDATE.OBJ,CALDATE.LST,NUL
MASM CALDISP.ASM,CALDISP.OBJ,CALDISP.LST,NUL
MASM CALMAIN.ASM,CALMAIN.OBJ,CALMAIN.LST,NUL
LINK CALMAIN+CALDATE+CALDISP+CALDATA,CAL.EXE,CAL.MAP;

MASM CALLDEMO.ASM,CALLDEMO.OBJ,CALLDEMO.LST,NUL
LINK CALLDEMO.OBJ,CALLDEMO.EXE,CALLDEMO.MAP;

MASM CNMAIN.ASM,CNMAIN.OBJ,CNMAIN.LST,NUL
MASM CNLIB.ASM,CNLIB.OBJ,CNLIB.LST,NUL
LINK CNMAIN+CNLIB,CN.EXE,CN.MAP;

MASM CFMAIN.ASM,CFMAIN.OBJ,CFMAIN.LST,NUL
MASM CFLIB.ASM,CFLIB.OBJ,CFLIB.LST,NUL
LINK CFMAIN+CFLIB,CF.EXE,CF.MAP;

MASM CTRACE.ASM,CTRACE.OBJ,CTRACE.LST,NUL
LINK CTRACE.OBJ,CTRACE.EXE,CTRACE.MAP;
```

| 项目 | 结果 |
|---|---|
| 4 个日历模块 | 各 0 Warning / 0 Severe |
| `CAL.EXE` | 0 Warning / 0 Severe |
| `CALLDEMO.EXE` | 0/0 |
| `CN.EXE` / `CF.EXE` | 0/0 |
| `CTRACE.EXE` | 0/0 |
| 日历 4 组输出 | 与作业 8 逐字节一致 |

### 7.2 踩坑记录

1. **`EXTRN` 写在段内会变成“当前段 External”**
   最初把 `EXTRN p_year:byte` 写在 `CSEG` 里，LST 符号表显示 `CSEG External`，LINK 报 `L2002: fixup overflow target external 'P_YEAR'`。把所有数据 `EXTRN` 移到 `CSEG segment` 之前后解决。

2. **多模块数据要放进 DGROUP**
   只在 `CALDATA` 里定义 `DATA`，其他模块用空 `DATA` 段 + `DGROUP GROUP DATA`，并 `ASSUME DS:DGROUP`，`MOV AX,DGROUP`。否则外部数据的偏移可能按错误的段解析。

3. **近调用参数顺序与远调用不同**
   主程序：

   ```asm
   push cur_year
   push cur_month
   call show_calendar
   ```

   近调用时栈帧是：

   ```text
   [bp+2] 返回 IP
   [bp+4] 最后压的月
   [bp+6] 先压的年
   ```

   最初照抄作业 8 的远调用 `[bp+8]=年/[bp+6]=月`，结果年和月互换，打印出 `0011` 和 100 多天的网格。近调用的正确写法是 `[bp+6]=年`、`[bp+4]=月`。

4. **多文件远调用要声明目标段**
   `CFMAIN` 不声明 `FCODE` 时，`call far ptr farlib` 被链接成 `9A 20 00 05 00`（CS 还是 CSEG，只是 IP 偏移到 FCODE 的物理位置）。加一个空的 `FCODE segment` 声明后才变成正确的 `9A 00 00 0D 00`。

5. **DOS 的 `INT 21H` 不保证保护所有寄存器**
   `CALLTRACE` 最初在 `showstack2` 里用 `SI` 保存栈指针，打印标签的 `INT 21H` 之后 `SI` 被破坏，读到 `[SI]=0000`。改成用 `BP` 保存指针，并把 IP/SP 先存到内存变量，才得到正确的 `[SP]=0013`、`[SP+2]=01CC`。

6. **8.3 文件名**
   `CALLTRACE.ASM` 基本名 9 个字符，DOS 侧会截断。构建时复制成 `CTRACE.ASM`（6 个字符），LST/OBJ/EXE 也都用 `CTRACE`。

7. **没有 STACK 段会警告**
   `CALLDEMO`、`CNMAIN`、`CFMAIN` 最初没有 `STACK` 段，LINK 报 `L4021: no stack segment`。加上 `STACK segment stack 'STACK' / dw 64 dup(0)` 后 0 警告。

8. **BAT 执行后不返回 `-c` 列表**
   与作业 8 相同：`DOSBox -c "BUILD" -c "RUN" -c "exit"` 中 BAT 不返回，改用 `ALL.BAT` + `CALL BUILD.BAT` / `CALL RUN.BAT` / `exit`。

## 八、小结

1. **多模块的核心是“段名 + PUBLIC/EXTRN + 组”**：同名 `CSEG` 让 LINK 合并成近段，`DGROUP` 让数据符号变成近偏移，`EXTRN` 必须放在段外，否则会被记成当前段的 External。
2. **宏是汇编期的文本替换**：`PRINTSTR` 展开成 3 条指令，`SAVEREGS` 展开成 6 条 `PUSH`，没有 CALL/RET 开销，但代码体积会增大。
3. **`CALL` 的机器码取决于目标在哪个段**：同段是 `E8 rel16`，跨段是 `9A off16 seg16`；多文件同段合并后仍是 `E8`，但位移由 LINK 在链接期填入（OBJ 里是 `0000 E`）。
4. **CS/IP/SP 的变化可以直接从栈看出来**：近调用 SP-2、`[SP]=IP`、CS 不变；远调用 SP-4、`[SP]=IP`、`[SP+2]=CS`、CS 改变；`RET` 是 `C3`，`RETF` 是 `CB`。
5. **多文件远调用比同文件远调用更容易出错**：调用方要知道目标段名，否则 LINK 可能用“当前段 + 连续偏移”凑地址。这是本次作业最有价值的坑。
